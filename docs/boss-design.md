# 보스 몬스터 기획 (확정 2026-11-10)

## Context
원안 메모(10·20분 중간 보스, 30분 최종 보스)는 방향은 좋지만 다음 내용이 비어 있다.
- 수치: HP, 데미지, 시간
- 이 게임 구조와의 연결: 한 사람이 좌우를 같이 조작함, 상대 차원의 웨이브가 내 쪽에 나옴, 좌우가 서로 다른 월드(LBG/RBG 레이어)임
- 보상, 실패 처리, 승리 조건

이 문서는 원안을 확장한 것이다. 끝에 구현 순서를 붙였다.
사용자 결정 사항(2026-11-10):
- 최종 보스는 **양쪽 화면에 동시에 보이는 하나의 보스**다. 별도 카메라로 오버레이하고, 충돌은 화면 좌표로 검사한다.
- 중간 보스 처치 보상은 **처치한 진영에 추가 보상 선택 1회**다.
- 중간 보스는 **죽기 전에는 사라지지 않는다**. 범위 밖으로 나가면 플레이어 근처에 다시 나타난다.

## 1. 공통 규칙

| 항목 | 내용 |
|---|---|
| 출현 진영 | 일반 웨이브처럼 **상대가 고른 차원의 보스가 내 쪽에 나온다** (`DimensionData`에 보스 등록 → 반대 진영 Spawner) |
| 출현 시각 | Spawner 경과 시간 10:00 / 20:00. 좌우 동시에 나온다. 서로 다른 보스 2마리를 동시에 상대하는 것이 이 게임 보스전의 핵심 난이도다 |
| 예고 | 출현 3초 전에 해당 화면 상단에 경고 배너를 띄운다 (경고음 없음). 화면 밖에 있으면 가장자리에 방향 화살표를 표시한다 |
| 출현 위치 | 플레이어 이동 방향 앞쪽, 스폰 링(11~13) 위 |
| HP 표시 | 일반 몬스터와 같은 방식으로 **몬스터 아래에** HP 바를 표시한다 (크기만 몸집에 맞춤) |
| 면역 | 넉백, 즉사(회전 칼날 ★10 등 `Kill()`), 분열·부활 대상에서 제외한다. 둔화·속박은 효과 30%만 받는다 |
| 사라지지 않음 | `DespawnOutOfCamera`를 쓰지 않는다. 카메라에서 20 이상 멀어지면 HP를 유지한 채 스폰 링 위로 재배치한다 (짧은 등장 연출 포함) |
| 겹침 | 별도 대응을 설계하지 않는다. 10분 보스를 20분까지 잡지 못하면 그대로 남아 20분 보스와 함께 상대한다. 30:00 최종 보스가 등장하면 모두 사라진다 |
| 일반 스폰 | 보스 생존 중에는 일반 스폰 개체수 ×0.7 (Spawner Count 보정 재사용). 보스 패턴이 읽힐 공간을 확보한다 |
| 처치 보상 | EXP 보석 대량 드롭 (10분 60, 20분 150) + **처치한 진영에 보스 보상 선택 1회**. 무기·무기 업그레이드만 3지선다로 나오고 너프 칸은 없다. 레벨업 UI를 재사용한다. **보스 보상 풀이 비어 있으면**(무기 6개 보유 + 모든 업그레이드 완료 등) 일반 레벨업 보상을 준다 |
| HP | **고정값**이다. 각 보스 표에 적힌 값을 그대로 쓰고, 웨이브 hpRate·보상 HP 보정·산정식을 적용하지 않는다. 플레이테스트로 값을 직접 조정한다 |
| 데미지 | 고정값이다. 웨이브 damageRate를 곱하지 않는다 |

| 숲 | 뿌리 거인 | 3배 | 추적 0.7 | **뿌리 장판**: 0.5초마다 발밑에 장판을 남긴다. 장판 안에서는 이동 40% 둔화 + 4 데미지/0.5초, 5초간 유지. 뒤를 쫓으며 카이팅하는 동선을 막는다 | HP 5,500 / 접촉 18 / 장판 반경 1.2 |

## 3. 20분 보스 (신경 써서 상대해야 함)

20:00은 러시 웨이브(약한 몹 ×1.5)라서 보스에 집중할 수 있는 시점이다. 보스 생존 중에는 일반 스폰 ×0.6.

### 숲: 도약하는 고목
- 순환: 추적 4초 → 도약.
- 도약 단계:
  1. 웅크림 0.3초.
  2. 공중 1.5초 (피격 불가, 본체 숨김).
  3. 그림자 원이 처음 0.8초 동안 플레이어를 따라온 뒤 위치를 고정하고 점점 진해진다.
  4. 착지: 반경 2.5, 데미지 30, 밀어냄.
- 착지 지점 둘레에 10분 보스의 뿌리 장판 6개를 남긴다 (테마 연결).
- HP 50% 이하: 도약을 3연속으로 한다 (각각 플레이어를 다시 노림, 공중 시간 1.2초).
- HP 17,500 / 접촉 25.

### 공장: 폭주 기관
- 화면(해당 진영 카메라 뷰) 경계에서 튕기며 등속 직선 이동한다. 속도 7, 대각 방향.
  - 경계는 매 프레임의 카메라 사각형이다. 플레이어가 움직이면 경계도 같이 움직인다.
- 8초마다 **과열**: 2.5초 정지 (증기 연출). 이때 받는 데미지 ×1.5. 공략 창이다.
- HP 50% 이하: 속도 9. 튕길 때마다 그 자리에 지뢰 1개를 남긴다 (2초 후 폭발, 반경 1.5, 데미지 20).
- HP 17,500 / 접촉 25.

### 폭풍: 판정의 고리
- 이동은 느린 선회. 고리 패턴 중에는 정지한다.
- 고리 패턴 (6초 쿨타임):
  1. **측정 2.0초**: 보스 중심, 반지름 = 현재 플레이어와의 거리. 점선 원이 실시간으로 따라간다.
  2. **고정 1.0초**: 중심과 반지름을 고정하고 실선으로 바꾼다.
  3. **판정 경고 1.2초**: 안쪽 또는 바깥쪽 영역을 붉게 채운다 (50:50, 같은 쪽 3연속 금지).
  4. **피해**: 붉은 영역에 있는 플레이어에게 35. 판정 기준은 플레이어 중심점이다.
- 경고에서 피해까지 1.2초 동안 플레이어는 6칸 이동할 수 있다 (속도 5). 원 근처에 있으면 항상 피할 수 있다.
- HP 50% 이하: 고리 2개 (반지름 = 거리 ±2). 띠 안쪽이 안전 또는 위험이다.
- HP 16,000 / 접촉 20.

## 4. 최종 보스 (30:00)

### 4.1 개념
두 차원을 동시에 침공하는 존재다. **하나의 보스가 좌우 화면 전체를 무대로 움직인다.** 화면 중앙선을 넘나든다.
한 사람이 두 화면을 동시에 보는 이 게임의 본질을 그대로 시험한다.

### 4.2 진입 연출 (모든 웨이브가 끝난 순간)
1. 양쪽의 모든 몬스터가 즉시 사라진다 (디졸브 연출, EXP 없음). 땅에 남은 EXP 보석은 전부 자동 흡수한다. 마지막 레벨업은 보스 전에 끝낸다.
2. 양쪽 Spawner 정지, 중간 보스 제거.
3. 양쪽 카메라의 `Follow`를 끈다. 화면이 그 자리에 고정된다.
4. 플레이어는 자기 화면 밖으로 나갈 수 없다 (뷰 경계 안쪽 0.5 여백으로 위치 고정).
5. 3초 경고 연출 (중앙선이 갈라지는 균열, BGM 전환) → 보스가 상단 중앙에서 내려온다.
6. 화면 최상단 전체 폭에 공유 HP 바 1개.

### 4.3 기술 구조 (사용자 지정 방식 + 보완)
- **보스 공간**: 좌우 화면을 이어 붙인 가상 좌표계다. 폭 = 좌 뷰 폭 + 우 뷰 폭, 높이 16. 카메라가 고정되므로 각 진영과의 변환은 평행 이동뿐이다.
  - `BossSpace.ToWorld(side, p)`, `BossSpace.FromWorld(side, worldPos)`.
- **렌더**: 보스 전용 레이어와 오버레이 카메라 (전체 화면, 좌우 카메라 위에 그림). 보스 본체와 모든 경고·탄은 보스 공간에 그린다.
- **보스 → 플레이어 판정 (사용자 방식)**: 플레이어 월드 좌표를 보스 공간으로 바꿔 원·선분(캡슐)·원 충돌을 직접 계산한다. 데미지는 `DamagePipeline`으로 넣는다. 플레이어 무적 시간도 그대로 적용된다.
- **플레이어 공격 → 보스 판정 (보완 제안)**: 무기 19종이 전부 `Physics2D` 겹침·트리거와 `TargetFinder`로 동작한다. 그래서 무기마다 화면 좌표 판정을 새로 넣는 대신 **보스 화면 위치를 각 진영 월드로 옮긴 투명 히트박스(`BossHitProxy`)**를 둔다.
  - 매 프레임 `BossSpace.ToWorld`로 위치를 맞춘다.
  - 보스 몸체가 그 진영 절반에 걸쳐 있을 때만 켠다.
  - 맞으면 공유 HP로 전달한다.
  - 판정 기준은 여전히 화면상 위치다. 모든 무기와 자동 조준이 수정 없이 보스를 맞힌다.
  - 순수 화면 좌표 판정을 원하면 무기 19종에 훅을 추가해야 한다 (비용이 큼).
- 보스가 한쪽 절반에만 있으면 반대쪽 무기는 맞히지 못한다. 그래서 보스는 자주 중앙선을 넘나들게 설계한다.
- 최종 보스 HP: 고정 **160,000** (초안, 플레이테스트로 조정).

### 4.4 패턴
| 패턴 | 예고 | 실행 | 수치 |
|---|---|---|---|
| **운석** | 보스 팔 들기 0.6초 → 발사 즉시 착탄 지점에 경고 원이 생기고 비행 동안 점점 채워진다 | 큰 에너지 구체가 포물선으로 1.8초 동안 천천히 난다 (높이 오프셋 + 지면 그림자). 진영당 3발: 1발은 플레이어 위치, 2발은 무작위 | 반경 1.6, 데미지 30 |
| **돌진** | 보스에서 대상 플레이어 쪽으로 화살표 1.0초 (좌우 번갈아 노림) | 등속 16으로 직선 이동, 전체 화면 경계에서 반사, 3초 또는 4회 반사 후 정지. 중앙선을 넘어 반대 화면도 휩쓴다. 끝나면 1.5초 숨 고르기 | 몸체 반경 1.8, 데미지 35 |
| **레이저** | 화면 전체를 가로지르는 가는 경고선 3줄 1.2초 → 0.2초 깜빡임 | 일직선 레이저 0.4초 | 폭 0.8, 데미지 40. 각 절반에 폭 2 이상의 안전 틈을 보장한다 |

### 4.5 페이즈와 공정성 규칙
- **P1 (HP 100~66%)**: 패턴을 하나씩 쓴다. 간격 2.5초. 위협이 생기는 화면을 **좌→우 0.5초 엇갈림**으로 낸다 (두 화면을 동시에 읽지 않아도 됨).
- **P2 (66~33%)**: 예고 −15%. 운석 진영당 5발, 레이저 4줄. 좌우 동시 위협 시작.
- **P3 (33% 이하)**: 조합 패턴 (레이저 + 운석, 돌진 후 즉시 운석). 착탄 지점에 3초 불장판.
- 같은 패턴 연속 금지. 모든 예고는 최소 1.0초 (P2·P3 포함).
- **격노**: 5분이 지나면 패턴 간격 1초. 무한 장기전을 방지한다.
- 처치 → `GameOverManager.TriggerVictory` (승리 조건을 "웨이브 종료"에서 "최종 보스 처치"로 바꾼다).

## 5. 구현 순서 (CLAUDE.md 서브에이전트 흐름)

새 런타임 폴더: `Assets/Resources/Script/BossSystem/`

1. **조사 (code-archivist)**: 플레이어 강제 이동 수단(플레이어 `Knockback` 유무), `HealthSystem.Kill` 면역 방법, LevelUpUI 재사용 지점, 레터박스·중앙 구분선 폭.
2. **중간 보스 (content-programmer)**
   - 키워드 추가: `OrbitBlades`, `PushPull`, `JumpSlam`, `ScreenBounce`(+과열), `RingJudge`.
   - `HazardZone`에 둔화 옵션 추가.
   - `BossData`(SO: HP, 출현 시각, 보상), `BossTag`(면역·재배치·HP 바 연결).
   - `DimensionData.midBosses[2]` → `DimensionApplier`가 반대 진영 `Spawner`에 전달.
   - Spawner 경과 시간 트리거로 출현.
   - 보스 보상: `RewardManager` 특수 풀 (Weapon + WeaponUpgrade, 너프 없음).
3. **최종 보스 (content-programmer)**
   - `BossSpace`, `FinalBossDirector`: 웨이브 종료 구독 → 정리 → `Follow` 비활성 → 플레이어 경계 고정.
   - `FinalBoss`(패턴 상태머신), `BossAttackResolver`(화면 좌표 판정), `BossHitProxy`.
   - `EventManager`에 `OnBossSpawned` / `OnBossDefeated` / `OnFinalBossStart` 추가.
   - `GameOverManager` 승리 조건 변경.
4. 공유 파일(`EventManager`, `Spawner`, `GameOverManager`, `DimensionData`)은 메인이 마지막에 직접 수정한다.
5. **리뷰·테스트 병렬** → 수정 루프 (최대 2회).
6. **unity-integrator**: 보스 프리팹 7종, BossData, 오버레이 카메라·보스 레이어, HUD 보스 HP 바, 빌더. 이후 `ArtResourceBuilder`, `InGameHudVisual`을 다시 실행한다.
7. **visual-designer**: 경고 연출, 그림자, 레이저, 균열, 사운드 연결.
8. `docs/balance-design.md`에 보스 고정 수치 표를 추가한다.

## 6. 검증
- EditMode: `BossSpace` 좌표 변환, 원·캡슐 판정, 고리 안팎 판정, 보스 HP가 웨이브 배율과 무관한지, 보상 풀이 비면 일반 보상으로 넘어가는지.
- PlayMode: `Spawner.DebugSkipWave`로 10:00 / 20:00 / 30:00까지 넘겨 출현·재배치·보상 창·최종 진입 순서(몬스터 소멸 → 카메라 고정 → 경계 고정 → 보스)를 확인한다.
- 실제 플레이: 차원 조합 3가지 각각 10·20분 보스 처치 시간을 재고, 최종 보스를 최선 빌드로 2~3분 안에 처치하는지 본다. 화면 캡처는 `.claude/tmp/`에 둔다.

## 7. 위험·확인 항목
- 최종 보스에서 무기 사거리가 짧은 근접 빌드(Sweep)는 불리할 수 있다. 돌진 후 숨 고르기 때 보스가 바닥 근처에 머물게 해서 보완한다.
- 오버레이 카메라와 분할 카메라의 정렬 순서, 레터박스 영역을 실제 화면으로 확인해야 한다.
